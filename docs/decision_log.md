# 项目决策日志（Decision Log）

> 本文件记录项目各阶段关键决策的选项、判断与理由，体现项目演进中的思考过程。
> 决策由项目成员赵伟翔、周恒毅讨论确定，AI 工具（Kimi / WorkBuddy）仅作为建议与执行辅助。

## 阶段一（2026-10-16 ～ 2026-10-19）

| # | 决策                      | 当时的选项                                                 | 我们的判断与理由                                                                                                  |
| - | ----------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 1 | 工作方式：双 AI 工具分工          | A.Kimi 负责规划与验收 + WorkBuddy 负责编码；B. 只用一个 AI 工具；        | 选 A。8.4 GB 的数据让我们意识到任务必须先被拆解才能动手。规划与验收由我们（借助 Kimi）把握，代码执行交给 WorkBuddy，两边上下文各自保持干净，且每一步产出都经过我们运行核对         |
| 2 | 选题：预测投诉处理结果（三分类）        | A. 叙述文本分类；B. 救济结果预测；C. 投诉量时间序列                        | 选 B。叙述文本字段大量缺失（需投诉人同意才公开），文本分类的可用数据缩水且我们难以判断其结果好坏；时间序列的预测目标不够明确。救济结果预测的输入输出都有明确的业务含义——我们选择我们能理解、能用常识验证的方向 |
| 3 | 评估指标：宏平均 F1             | A. 准确率；B. 宏平均 F1                                      | 选 B。多数类占 63.6%，永远预测多数类准确率就有 0.64，准确率在该任务上没有区分度。宏平均 F1 对每个类别一视同仁，能暴露模型在稀有类上的失败                             |
| 4 | 金钱救济类（1.4%）的定位          | A. 视为数据质量问题尝试规避；B. 视为研究价值                             | 选 B。稀有但重要的类别正是简单规则失效、值得系统研究的地方。它直接决定了指标选择和后续阶段的改进方向                                                       |
| 5 | 采样策略：20 万行随机采样（种子 42）   | A. 强行全量读入；B. 分块采样                                     | 选 B。8.4 GB 超过内存，分块 + 固定种子兼顾可运行性与可复现性。同时明确记录假设：采样代表性留待阶段二用全量统计验证                                           |
| 6 | Product 名称归一化           | A. 保留原始 20 类；B. 合并新旧命名至 13 类                          | 选 B。同一产品在不同年代的命名不同，不合并会让模型学到"命名年份"这种伪模式                                                                   |
| 7 | Git 操作方式：GitHub Desktop | A. 命令行 git；B. GitHub Desktop                          | 选 B。系统未安装命令行 git（"不是内部或外部命令"），而机器上已有 GitHub Desktop，图形界面可以完成提交、推送、打标签全部需求                                 |
| 8 | 原始数据入库问题                | A. 提交 8.4 GB 到 GitHub；B. gitignore 排除 + README 记录复现方法 | 选 B。GitHub 单文件限制 100 MB，大文件入库必然失败。排除原始数据并在 README 写明"运行 src/sample\_data.py 可重新生成样本"，同时满足可复现性要求           |
